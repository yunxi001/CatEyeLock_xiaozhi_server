## 4. seq_id 使用规范

**规范文档**：`docs/my_docs/seq_id使用规范与注意事项.md`

**核心规则**：
1. **格式**：`时间戳_序号`（如 `1702234567890_0`）
2. **传递**：App → Server → ESP32，保持原始 seq_id
3. **携带规则**：
   - ✅ 需要携带：所有命令及其响应（lock_control、dev_control、user_mgmt、query、esp32_ack、ack）
   - ❌ 不需要携带：所有主动上报（status_report、event_report、log_report、door_opened_report、password_report、user_mgmt_result、heartbeat、face_result）

**验证结果**：

### 8.3 seq_id 透传机制

**验证结果**：✅ 完全正确

**工作流程**：
```
App 发送: seq_id = "app_1702234567890_001"
    ↓ (透传)
Server → ESP32: seq_id = "app_1702234567890_001"
    ↓ (原样返回)
ESP32 → Server: seq_id = "app_1702234567890_001"
    ↓ (直接转发)
Server → App: seq_id = "app_1702234567890_001"
```

**关键实现**：
- commandProxyHandler：直接透传 App 的 seq_id
- ackHandler：直接转发原始消息
- 全程无需 ID 映射
