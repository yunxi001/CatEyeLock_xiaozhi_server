# 门锁配置加载分析

## 核心结论

**门锁配置使用独立的配置文件，不受 manager-api 影响！**

## 配置文件层级

### 1. 系统主配置（受 manager-api 影响）

**文件位置**：

- `config.yaml` - 默认配置
- `data/.config.yaml` - 用户配置

**加载逻辑**：

```python
# config/config_loader.py
if custom_config.get("manager-api", {}).get("url"):
    # 从 API 获取配置（覆盖 config.yaml）
    config = get_config_from_api(custom_config)
else:
    # 使用本地配置
    config = merge_configs(default_config, custom_config)
```

**影响范围**：

- `selected_module`（ASR、LLM、TTS、VLLM、VAD、Memory、Intent）
- 插件配置
- 服务器配置
- 日志配置
- 等等...

### 2. 门锁独立配置（不受 manager-api 影响）

**文件位置**：

- `config/doorlock_config.yaml` - 门锁专用配置

**加载逻辑**：

```python
# core/providers/doorlock/doorlock_database.py

def _load_doorlock_config() -> dict:
    """加载智能门锁独立配置文件"""
    # 直接从文件系统读取，不经过 config_loader
    current_file = Path(__file__)
    project_root = current_file.parent.parent.parent.parent
    config_path = project_root / "config" / "doorlock_config.yaml"

    if not config_path.exists():
        raise FileNotFoundError(f"门锁配置文件不存在: {config_path}")

    from ruamel.yaml import YAML
    yaml = YAML()
    with open(config_path, 'r', encoding='utf-8') as f:
        config = yaml.load(f)

    return config
```

**影响范围**：

- MySQL 数据库连接（门锁专用数据库）
- 快递看护模式配置
- 意图识别配置
- 人脸识别配置
- 性能配置

## 为什么门锁配置要独立？

### 1. 数据隔离

门锁功能使用独立的数据库：

```yaml
mysql:
  database: smart_doorlock # ← 独立数据库
```

与系统主数据库分离，避免数据混乱。

### 2. 配置稳定性

门锁配置不应该被 manager-api 覆盖：

- 数据库连接信息
- 快递看护参数
- 人脸识别设置

这些配置需要保持稳定，不应该随着 API 配置变化而变化。

### 3. 部署灵活性

可以独立配置门锁功能，不影响系统其他部分：

- 可以单独修改门锁数据库连接
- 可以调整快递看护参数
- 不需要重新配置整个系统

### 门锁使用的系统配置

门锁功能**只使用系统配置中的 VLLM 模块**：

**文件**：`config/doorlock_config.yaml` 注释

```yaml
# 注意：VLLM 配置复用系统配置（config.yaml 的 selected_module.VLLM）
```

**原因**：

- VLLM 配置在系统主配置中（`selected_module.VLLM`）
- 从 API 加载配置时，VLLM 配置也会被更新

### 门锁不使用的系统配置

门锁功能**不使用**以下系统配置：

- ❌ ASR（语音识别）- 门锁有自己的语音处理
- ❌ LLM（大语言模型）- 门锁使用 VLLM
- ❌ TTS（语音合成）- 门锁有自己的 TTS
- ❌ 插件配置 - 门锁有自己的工具函数
- ❌ MySQL 配置 - 门锁使用独立配置

## 总结

### 关键点

1. **门锁配置完全独立**
   - 使用独立的配置文件 `config/doorlock_config.yaml`
   - 不经过 `config_loader.py`
   - 不受 manager-api 影响

2. **系统配置受 manager-api 影响**
   - `config.yaml` 和 `data/.config.yaml`
   - 通过 `config_loader.py` 加载
   - 如果 `manager-api.url` 有值，从 API 获取配置

3. **门锁只使用系统的 VLLM 配置**
   - 其他配置（MySQL、快递看护等）都从独立配置文件读取
   - VLLM 配置从系统配置中获取（可能来自 API）

4. **配置加载时机**
   - 系统配置：启动时加载
   - 门锁配置：使用门锁功能时加载（延迟加载）

### 回答你的问题

**Q: 从 API 读取配置的情况下，门锁相关的配置还加载吗？**

**A: 是的，门锁配置始终会加载，但加载方式不同：**

1. **门锁独立配置**（`config/doorlock_config.yaml`）
   - ✅ 始终从文件加载
   - ✅ 不受 manager-api 影响
   - ✅ 包含：MySQL、快递看护、意图识别、人脸识别等配置

2. **门锁使用的系统配置**（VLLM）
   - ✅ 从系统配置中获取
   - ✅ 如果从 API 加载，使用 API 返回的 VLLM 配置
   - ✅ 如果使用本地配置，使用 `config.yaml` 的 VLLM 配置

**Q: 还是说其他部分会加载门锁修改的配置（比如使用的时候？）**

**A: 是的，门锁配置是在使用时加载的（延迟加载）：**

1. **加载时机**：
   - 当初始化 `DoorlockDatabase` 时
   - 当使用门锁 HTTP API 时
   - 当使用门锁工具函数时

2. **加载方式**：
   - 直接调用 `_load_doorlock_config()`
   - 从文件系统读取 `config/doorlock_config.yaml`
   - 不经过系统配置加载流程

3. **独立性**：
   - 门锁配置与系统配置完全独立
   - 修改门锁配置不影响系统配置
   - 修改系统配置（或从 API 加载）不影响门锁配置
