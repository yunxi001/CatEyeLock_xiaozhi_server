# 统一错误码修改计划

## 1. 修改目标

将 App 协议中的两套错误码体系（server_ack 使用 0-5，ESP32 ack 使用 0-10）统一为单一的 0-10 错误码体系。

## 2. 问题分析

### 2.1 当前状态

| 错误码类型   | 使用场景                      | 错误码范围      | 实际使用情况  |
| ------------ | ----------------------------- | --------------- | ------------- |
| server_ack   | 服务器接收 App 消息的即时确认 | 0-5（协议定义） | 只用了 0 和 5 |
| ESP32 ack    | ESP32 执行命令后的结果反馈    | 0-10            | 完整使用      |
| 业务错误响应 | 命令代理处理器的错误响应      | 0-10            | 完整使用      |

### 2.2 存在的问题

1. **协议文档不一致**：App 协议文档定义了两套错误码，容易混淆
2. **实际使用不匹配**：server_ack 协议定义了 0-5，但实际只用了 0 和 5
3. **维护成本高**：需要维护两套错误码的映射和文档
4. **代码已统一**：代码实现已经使用统一的 ErrorCode 类（0-10）

## 3. 修改方案

### 3.1 核心原则

1. **统一使用 0-10 错误码**：所有错误响应都使用统一的错误码体系
2. **明确使用场景**：区分 server_ack（接收确认）和业务响应（执行结果）
3. **保持向后兼容**：代码实现不需要大改，只需更新文档和注释

### 3.2 错误码使用规范

#### 3.2.1 server_ack 错误码（简化版）

server_ack 只用于确认"服务器是否成功接收消息"，不涉及业务逻辑：

| code | 含义     | 使用场景                          |
| ---- | -------- | --------------------------------- |
| 0    | 成功     | 消息已接收，将转发给 ESP32 或处理 |
| 3    | 参数错误 | 消息格式错误、缺少必填字段        |
| 8    | 未认证   | App 未完成 hello 认证             |
| 9    | 重复消息 | seq_id 重复（防重放）             |

**说明**：

- 不使用 1（设备离线）：设备状态应在业务响应中返回
- 不使用 2（设备忙）：设备状态应在业务响应中返回
- 不使用 4（不支持）：消息类型不支持应返回参数错误（3）
- 不使用 5（超时）：server_ack 是即时响应，不存在超时
- 不使用 6（硬件故障）：硬件状态应在业务响应中返回
- 不使用 7（资源已满）：资源状态应在业务响应中返回
- 不使用 10（内部错误）：服务器内部错误应在业务响应中返回

#### 3.2.2 业务响应错误码（完整版）

业务响应（如 lock_control、dev_control 的 error 响应）使用完整的 0-10 错误码：

| code | 含义     | 使用场景              |
| ---- | -------- | --------------------- |
| 0    | 成功     | 操作成功完成          |
| 1    | 设备离线 | ESP32 未连接服务器    |
| 2    | 设备忙   | 正在执行其他操作      |
| 3    | 参数错误 | 命令格式或参数无效    |
| 4    | 不支持   | 不支持的命令或操作    |
| 5    | 超时     | 等待响应超时          |
| 6    | 硬件故障 | 硬件异常或不可用      |
| 7    | 资源已满 | 指纹/NFC 存储已满     |
| 8    | 未认证   | 用户未登录或权限不足  |
| 9    | 重复消息 | seq_id 重复（防重放） |
| 10   | 内部错误 | 未知内部异常          |

#### 3.2.3 ESP32 ack 错误码（完整版）

ESP32 ack 使用完整的 0-10 错误码，与业务响应保持一致。

### 4.3 测试验证

#### 4.3.1 单元测试（可选）

创建测试文件验证错误码使用：

**文件**：`main/xiaozhi-server/test/test_error_codes.py`

```python
"""错误码使用测试"""
import pytest
from core.constants.error_codes import ErrorCode, is_valid_error_code, get_error_message


def test_error_code_range():
    """测试错误码范围验证"""
    assert is_valid_error_code(0) == True
    assert is_valid_error_code(10) == True
    assert is_valid_error_code(-1) == False
    assert is_valid_error_code(11) == False


def test_server_ack_codes():
    """测试 server_ack 应该使用的错误码"""
    # server_ack 简化使用的错误码
    valid_server_ack_codes = [
        ErrorCode.SUCCESS,           # 0
        ErrorCode.PARAM_ERROR,       # 3
        ErrorCode.UNAUTHORIZED,      # 8
        ErrorCode.DUPLICATE_MESSAGE, # 9
    ]

    for code in valid_server_ack_codes:
        assert is_valid_error_code(code)
        assert get_error_message(code) != "未知错误"


def test_business_response_codes():
    """测试业务响应应该使用的完整错误码"""
    # 业务响应可以使用所有 0-10 错误码
    for code in range(11):
        assert is_valid_error_code(code)
        assert get_error_message(code) != "未知错误"


def test_error_messages():
    """测试错误消息获取"""
    assert get_error_message(ErrorCode.SUCCESS) == "成功"
    assert get_error_message(ErrorCode.DEVICE_OFFLINE) == "设备离线"
    assert get_error_message(ErrorCode.TIMEOUT) == "超时"
    assert get_error_message(999) == "未知错误"
```
