# 智能猫眼门锁系统 - 服务器端架构说明

## 1. 概述

### 1.1 服务器定位

服务器（xiaozhi-server）是智能猫眼门锁系统的**核心枢纽**，承担以下关键职责：

```
┌─────────────────────────────────────────────────────────────────┐
│                         云端服务器                               │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────────┐  │
│  │  连接管理   │  │  消息路由   │  │      AI 推理引擎        │  │
│  │  ESP32/App  │  │  双向转发   │  │  人脸识别/语音交互      │  │
│  └─────────────┘  └─────────────┘  └─────────────────────────┘  │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────────┐  │
│  │  数据存储   │  │  业务逻辑   │  │      实时推送           │  │
│  │  MySQL      │  │  权限/通知  │  │  状态/事件/到访         │  │
│  └─────────────┘  └─────────────┘  └─────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
         ▲                                           ▲
         │ WebSocket (8000)                          │ WebSocket (8000)
         │ /xiaozhi/v1/                              │ /ws/app
         ▼                                           ▼
┌─────────────────┐                       ┌─────────────────┐
│     ESP32       │                       │      App        │
│   (门锁硬件)    │                       │   (用户手机)    │
└─────────────────┘                       └─────────────────┘
```

### 1.2 技术栈

| 组件 | 技术选型 | 说明 |
|------|----------|------|
| 运行时 | Python 3.10 | 异步编程 |
| 通信协议 | WebSocket | 双向实时通信 |
| 数据库 | MySQL | 持久化存储 |
| AI 引擎 | face_recognition | 人脸识别 |

## 2. 核心功能

### 2.1 连接管理

服务器管理两类 WebSocket 连接：

#### ESP32 设备连接
- **端点**：`ws://{server}:8000/xiaozhi/v1/`
- **认证**：HTTP Header `Authorization: Bearer <token>`
- **标识**：`device_id`（设备 MAC 地址）
- **生命周期**：设备开机连接，断电断开

#### App 客户端连接
- **端点**：`ws://{server}:8000/ws/app`
- **认证**：`hello` 消息携带 `device_id` + `app_id`
- **标识**：`app_id`（用户唯一标识）
- **生命周期**：App 打开时连接，关闭时断开

#### 连接关系
```
ConnectionManager (单例)
├── esp32_connections: {device_id: ConnectionHandler}
└── app_connections: {device_id: [AppConnectionHandler, ...]}
```

一个 ESP32 设备可以关联多个 App（家庭成员共享），服务器负责维护这种一对多关系。

### 2.2 消息路由

服务器作为消息中转站，实现 ESP32 与 App 之间的双向通信：

#### ESP32 → Server → App（上行）
```
ESP32 上报消息          Server 处理              App 接收
─────────────────────────────────────────────────────────────
status_report    →    存储 + 转发      →    实时状态更新
event_report     →    存储 + 转发      →    事件通知
log_report       →    存储 + 转发      →    开锁记录
ack              →    转发             →    命令执行结果
user_mgmt_result →    转发             →    用户管理结果
人脸图像(二进制) →    AI识别 + 推送   →    visit_notification
```

#### App → Server → ESP32（下行）
```
App 发送命令            Server 处理              ESP32 接收
─────────────────────────────────────────────────────────────
lock_control     →    添加msg_id + 转发  →    执行开锁/关锁
dev_control      →    添加msg_id + 转发  →    控制蜂鸣器/灯
user_mgmt        →    添加msg_id + 转发  →    管理指纹/NFC
system           →    模式切换 + 转发    →    启停监控模式
```

### 2.3 AI 推理

#### 人脸识别流程
```
1. ESP32 发送人脸图像（BinaryProtocol2, type=2）
2. Server 解析 JPEG 数据
3. face_recognition 库提取人脸特征
4. 与数据库中已注册人脸比对
5. 检查访问权限（时间段、有效期等）
6. 生成识别结果 + 问候语
7. 返回 face_result 给 ESP32
8. 推送 visit_notification 给 App
```

#### 识别结果类型
| result | 说明 | 后续动作 |
|--------|------|----------|
| `known` | 已注册用户 | 检查权限，决定是否开锁 |
| `unknown` | 陌生人 | 拒绝开锁，推送通知 |
| `no_face` | 未检测到人脸 | 忽略 |
| `error` | 识别错误 | 记录日志 |

### 2.4 实时推送

服务器主动向 App 推送以下通知：

| 通知类型 | 触发条件 | 包含数据 |
|----------|----------|----------|
| `device_status` | ESP32 上线/下线 | status, reason |
| `status_report` | 传感器状态变化 | 电量、光照、锁状态 |
| `event_report` | 关键事件发生 | 门铃、PIR、撬锁等 |
| `log_report` | 开锁尝试 | 方式、用户、结果 |
| `visit_notification` | 人脸识别完成 | 识别结果、人脸图片 |
| `ack` | ESP32 命令执行完成 | 执行结果 |

```
ESP32 上报数据:
```

### 3.2 数据处理逻辑

#### 状态上报 (status_report)
```python
# 1. 解析消息
data = msg_json.get("data", {})
battery = data.get("bat")
lux = data.get("lux")
lock_state = data.get("lock")
light_state = data.get("light")

# 2. 内存缓存（快速查询）
conn.iot_descriptors["smart_doorlock"] = {
    "battery": battery,
    "lock_state": "open" if lock_state == 1 else "closed",
    ...
}

# 3. 持久化存储
db.save_device_status(device_id, battery, lux, lock_state, light_state)

# 4. 实时转发给 App
for app_conn in manager.get_app_conns(device_id):
    await app_conn.websocket.send(json.dumps(msg_json))
```

#### 人脸识别
```python
# 1. 解析二进制数据
jpeg_data = face_service.parse_image(message)

# 2. AI 识别
result = face_service.recognize(jpeg_data)

# 3. 权限检查
if result.result == "known":
    access_granted, deny_reason = face_service.check_permission(result.person.id)

# 4. 保存到访记录
visit_id = face_service.save_visit_record(result, access_granted, deny_reason, jpeg_data)

# 5. 返回结果给 ESP32
response = {
    "type": "face_result",
    "result": result.result,
    "user_id": result.person.id if result.person else None,
    "access": {"granted": access_granted, "reason": access_reason}
}
await conn.websocket.send(json.dumps(response))

# 6. 推送通知给 App（含图片）
notification = {
    "type": "visit_notification",
    "data": {
        "visit_id": visit_id,
        "person_name": result.person.name if result.person else "陌生人",
        "image": base64.b64encode(jpeg_data).decode()
    }
}
for app_conn in manager.get_app_conns(device_id):
    await app_conn.websocket.send(json.dumps(notification))
```

### 3.3 消息确认机制

#### ESP32 协议（msg_id + ack）
```
Server → ESP32: {"type": "lock_control", "msg_id": "cmd_1001", "command": "unlock"}
ESP32 → Server: {"type": "ack", "msg_id": "cmd_1001", "code": 0, "msg": "OK"}
Server → App:   {"type": "ack", "msg_id": "cmd_1001", "code": 0, "msg": "OK"}
```

#### App 协议（seq_id + server_ack）
```
App → Server:   {"type": "lock_control", "seq_id": "app_001", "command": "unlock"}
Server → App:   {"type": "server_ack", "seq_id": "app_001", "code": 0, "msg": "已接收"}
```

### 5.2 核心类

#### ConnectionManager
```python
class ConnectionManager:
    """全局连接管理器，单例模式"""
    
    esp32_connections: Dict[str, ConnectionHandler]  # ESP32 连接
    app_connections: Dict[str, List[AppConnectionHandler]]  # App 连接
    
    def register_esp32(device_id, conn)      # 注册 ESP32，通知 App 上线
    def unregister_esp32(device_id, reason)  # 注销 ESP32，通知 App 下线
    def register_app(device_id, conn)        # 注册 App
    def unregister_app(device_id, conn)      # 注销 App
    def get_esp32_conn(device_id)            # 获取 ESP32 连接
    def get_app_conns(device_id)             # 获取所有关联 App
```

#### ConnectionHandler（ESP32）
```python
class ConnectionHandler:
    """ESP32 连接处理器"""
```

#### AppConnectionHandler
```python
class AppConnectionHandler:
    """App 连接处理器"""
    
    device_id: str    # 关联的设备 ID
```

#### TextMessageHandler（抽象基类）
```python
class TextMessageHandler(ABC):
    """消息处理器基类"""
    
    @property
    @abstractmethod
    def message_type(self) -> TextMessageType:
        """返回处理的消息类型"""
        pass
    
    @abstractmethod
    async def handle(self, conn, msg_json: Dict[str, Any]) -> None:
        """处理消息"""
        pass
```

## 6. 安全机制

### 6.1 连接认证

| 连接类型 | 认证方式 | 验证内容 |
|----------|----------|----------|
| ESP32 | HTTP Header | `Authorization: Bearer <token>` |
| App | hello 消息 | `device_id` + `app_id` + ESP32 在线检查 |

### 6.2 消息防重放

#### ESP32 端
- Server 下发命令携带唯一 `msg_id`
- ESP32 维护最近 100 条 msg_id 缓存
- 重复 msg_id 直接忽略

#### App 端
- App 发送消息携带 `seq_id`
- Server 维护 SeqIdCache（按 app_id 分组）
- 重复 seq_id 返回 `server_ack` code=5

### 6.3 路径安全

媒体文件下载时进行路径遍历攻击检查：
```python
real_path = os.path.realpath(full_path)
real_root = os.path.realpath(MEDIA_ROOT)
if not real_path.startswith(real_root):
    # 拒绝访问
```

### 6.4 异常检测

- 连续 5 次开锁失败触发警报
- 撬锁检测立即上报并触发警报
- 低电量提前预警
