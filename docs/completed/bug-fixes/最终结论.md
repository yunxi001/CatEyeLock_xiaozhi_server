### 3. 问题根源分析

#### 为什么会出现进度条和编码错误？

1. **系统使用FunASR**（config.yaml中的配置）
2. **FunASR是本地模型**，会输出进度条
3. **进度条包含Unicode字符**（`█`）
4. **某个输出流使用ASCII编码**，无法处理Unicode字符
5. **触发编码错误**

#### 为什么98d28cb3正常，7c7b88dc出错？

**最可能的原因**：`data/.config.yaml`在两个版本之间被修改了

由于`data/.config.yaml`不在版本控制中，我们无法直接查看其历史。但根据配置加载逻辑，有以下可能：

##### 可能性1：manager-api.url被清空（最可能）

**98d28cb3版本时**：

```yaml
manager-api:
  url: http://your-manager-api:8002/xiaozhi # 有值
  secret: 2c7b52c9-a9a3-4025-a7b7-51d8b44ab35b
```

- 系统从API加载配置
- API返回的配置中ASR为DoubaoStreamASR
- 使用DoubaoStreamASR（远程API，无进度条）
- 正常运行

**7c7b88dc版本时**：

```yaml
manager-api:
  url: # 被清空或注释
  secret: 2c7b52c9-a9a3-4025-a7b7-51d8b44ab35b
```

- 系统不从API加载配置
- 使用本地config.yaml的配置
- ASR为FunASR（本地模型）
- 输出进度条，触发编码错误

##### 可能性2：manager-api服务不可用

- manager-api.url有值，但服务无法访问
- 配置加载失败，fallback到本地配置
- 使用FunASR，出现问题

##### 可能性3：API返回的配置变化

- API正常连接，但返回的配置中ASR改为了FunASR
- 但这种可能性较小，因为通常API配置不会随意改变

### 4. 为什么selected_module显示为00000000000000？

这个现象**不是问题的根本原因**，而是**日志系统的默认行为**。

查看`config/logger.py`：

```python
def formatter(record):
    """为没有 tag 的日志添加默认值，并处理动态模块字符串"""
    record["extra"].setdefault("tag", record["name"])
    # 如果没有设置 selected_module，使用默认值
    record["extra"].setdefault("selected_module", "00000000000000")
    # ...
```

在连接初始化早期，`selected_module`还未设置时，日志会显示默认值`"00000000000000"`。

但实际上，系统后续会正确加载配置并使用FunASR。

## 最终结论

### 问题根源

**你的系统配置为使用FunASR（本地模型），而FunASR输出的进度条包含Unicode字符，在ASCII编码的输出流中触发了编码错误。**

### 为什么98d28cb3正常？

**最可能的原因是：98d28cb3版本时，你的`data/.config.yaml`中`manager-api.url`有值，系统从API获取配置并使用DoubaoStreamASR（远程API，无进度条）。**

在7c7b88dc版本时，`manager-api.url`被清空或manager-api服务不可用，系统fallback到本地config.yaml的FunASR配置，导致出现进度条和编码错误。

### 为什么代码没有变化却出现问题？

因为**配置文件（data/.config.yaml）不在版本控制中**，它的变化不会被Git记录。代码本身没有问题，是配置的变化导致了行为的改变。

## 解决方案

### 方案1：恢复使用manager-api（如果你有）

修改`main/xiaozhi-server/data/.config.yaml`：

```yaml
manager-api:
  url: http://你的manager-api地址:8002/xiaozhi # 填写正确的URL
  secret: 2c7b52c9-a9a3-4025-a7b7-51d8b44ab35b
```

然后在manager-api的Web界面中配置ASR为DoubaoStreamASR。

### 方案2：修改config.yaml使用DoubaoStreamASR

如果你不使用manager-api，直接修改`main/xiaozhi-server/config.yaml`：

```yaml
selected_module:
  ASR: DoubaoStreamASR # 改为DoubaoStreamASR
```

并确保有DoubaoStreamASR的完整配置。

### 方案3：禁用FunASR进度条

如果你想继续使用FunASR，修改`main/xiaozhi-server/core/providers/asr/fun_local.py`：

```python
import os

class ASRProvider(ASRProviderBase):
    def __init__(self, config: dict, delete_audio_file: bool):
        super().__init__()

        # 禁用tqdm进度条
        os.environ['TQDM_DISABLE'] = '1'

        # ... 其余代码
```

### 方案4：强制UTF-8编码（兜底）

在`main/xiaozhi-server/app.py`开头添加：

```python
import sys
import io

# 强制使用UTF-8编码
if sys.stdout.encoding != 'utf-8':
    sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')
if sys.stderr.encoding != 'utf-8':
    sys.stderr = io.TextIOWrapper(sys.stderr.buffer, encoding='utf-8')
```
