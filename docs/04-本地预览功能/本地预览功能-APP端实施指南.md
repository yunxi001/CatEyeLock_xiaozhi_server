## 1. 功能概述

### 1.1 目标

实现 APP 端对 ESP32 本地预览功能的远程控制，允许用户通过手机 APP 启动/停止 ESP32 的本地预览功能。

### 1.2 用户场景

**场景1：远程启动本地预览**

```
用户在 APP 中点击"打开本地预览"按钮
→ APP 发送请求到服务器
→ 服务器转发命令到 ESP32
→ ESP32 启动本地预览
→ APP 显示"已打开本地预览"
```

**场景2：远程停止本地预览**

```
用户在 APP 中点击"关闭本地预览"按钮
→ APP 发送请求到服务器
→ 服务器转发命令到 ESP32
→ ESP32 停止本地预览
→ APP 显示"已关闭本地预览"
```

### 1.3 功能特点

- 📱 远程控制 ESP32 本地预览
- 🔄 实时状态同步
- ⚡ 快速响应
- 🎨 友好的用户界面
- ⚠️ 完善的错误提示

## 2. 需要实现的功能

### 2.1 用户界面（UI）

#### 2.1.1 控制按钮

**位置**：

- 放在设备控制页面
- 与"监控模式"按钮并列显示

**按钮状态**：

- **未启动状态**：
  - 显示文字："打开本地预览" 或图标 📺
  - 按钮颜色：灰色或默认色
  - 可点击

- **运行中状态**：
  - 显示文字："关闭本地预览" 或图标 📺
  - 按钮颜色：高亮色（如蓝色、绿色）
  - 可点击

- **禁用状态**：
  - 显示文字："本地预览（不可用）"
  - 按钮颜色：浅灰色
  - 不可点击
  - 显示原因：如"监控模式运行中"

**交互设计**：

- 点击按钮后显示加载动画（转圈或进度条）
- 禁用按钮，防止重复点击
- 收到响应后更新按钮状态
- 显示操作结果提示（Toast/Snackbar）

#### 2.1.2 状态指示

**显示内容**：

- 本地预览是否运行中
- 运行时长（可选）
- 互斥冲突提示

**界面示例**：

```
┌─────────────────────────────┐
│  设备控制                    │
├─────────────────────────────┤
│                             │
│  [监控模式]  [本地预览]     │
│   (运行中)    (未启动)      │
│                             │
│  💡 提示：监控模式运行时，   │
│     无法启动本地预览         │
│                             │
└─────────────────────────────┘
```

#### 2.1.3 互斥提示

**当监控模式运行时**：

- 本地预览按钮显示为禁用状态（灰色）
- 显示提示信息："监控模式运行中"
- 点击时弹出提示："请先关闭监控模式"

**当本地预览运行时**：

- 监控模式按钮显示为禁用状态（灰色）
- 显示提示信息："本地预览运行中"
- 点击时弹出提示："请先关闭本地预览"

### 2.2 网络通信

#### 2.2.1 HTTP API 调用

**需要实现的 API 接口**：

**1. 启动本地预览**

- 请求方法：POST
- 请求路径：`/api/device/{device_id}/local_preview`
- 请求体：`{"action": "start"}`
- 超时时间：10 秒

**2. 停止本地预览**

- 请求方法：POST
- 请求路径：`/api/device/{device_id}/local_preview`
- 请求体：`{"action": "stop"}`
- 超时时间：10 秒

**3. 查询状态（可选）**

- 请求方法：GET
- 请求路径：`/api/device/{device_id}/local_preview/status`
- 超时时间：5 秒

#### 2.2.2 响应处理

**成功响应格式**：

```
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "running"  // 或 "stopped"
  }
}
```

**失败响应格式**：

```
{
  "code": 1001,
  "message": "Monitor mode is active",
  "data": null
}
```

**需要处理的响应**：

- 解析 JSON 响应
- 根据 code 判断成功/失败
- 提取 message 显示给用户
- 更新 UI 状态

#### 2.2.3 错误码处理

**需要识别的错误码**：

| 错误码 | 含义           | 用户提示                             |
| ------ | -------------- | ------------------------------------ |
| 0      | 成功           | "操作成功"                           |
| 1001   | 监控模式运行中 | "监控模式正在运行，请先关闭监控模式" |
| 1002   | 人脸识别运行中 | "人脸识别正在进行，请稍后再试"       |
| 1003   | 摄像头不可用   | "摄像头暂时不可用，请稍后再试"       |
| 1004   | 设备离线       | "设备离线，无法操作"                 |
| 1005   | 系统错误       | "系统错误，请稍后再试"               |
| 1006   | 权限不足       | "您没有权限执行此操作"               |

### 2.3 状态管理

#### 2.3.1 本地状态

**需要维护的状态**：

- `localPreviewActive`: boolean - 本地预览是否运行中
- `isLoading`: boolean - 是否正在加载
- `lastError`: string - 最后一次错误信息

**状态更新时机**：

- 点击按钮时：设置 `isLoading = true`
- 收到成功响应时：更新 `localPreviewActive`，设置 `isLoading = false`
- 收到失败响应时：设置 `lastError`，设置 `isLoading = false`
- 超时时：设置 `lastError = "操作超时"`，设置 `isLoading = false`

#### 2.3.2 状态同步

**实时同步方式**：

**方式1：WebSocket 推送（推荐）**

- 服务器主动推送状态变化
- 实时性高，延迟低
- 需要维护 WebSocket 连接

**方式2：轮询查询**

- 定时调用状态查询 API
- 实现简单，但有延迟
- 建议间隔：5-10 秒

**同步场景**：

- 其他用户通过 APP 改变状态
- 用户通过语音命令改变状态
- ESP32 自动停止（如超时）

#### 2.3.3 离线处理

**设备离线时**：

- 禁用所有控制按钮
- 显示"设备离线"提示
- 按钮变为灰色不可点击

**设备重新上线时**：

- 恢复按钮可用状态
- 查询当前状态并更新 UI

### 2.4 用户体验优化

#### 2.4.1 加载状态

**点击按钮后**：

- 显示加载动画（转圈图标）
- 禁用按钮，防止重复点击
- 显示提示文字："正在处理..."

**加载动画位置**：

- 按钮内部（替换文字）
- 或按钮旁边（小图标）

#### 2.4.2 操作反馈

**成功反馈**：

- 显示 Toast/Snackbar："已打开本地预览" 或 "已关闭本地预览"
- 更新按钮状态和文字
- 播放成功音效（可选）

**失败反馈**：

- 显示 Toast/Snackbar：错误提示文字
- 恢复按钮到之前的状态
- 提供"重试"按钮（可选）

**超时反馈**：

- 显示 Toast/Snackbar："操作超时，请检查网络连接"
- 提供"重试"按钮

#### 2.4.3 重试机制

**失败后的重试**：

- 显示"重试"按钮
- 点击后重新发送请求
- 建议最多重试 2 次

**自动重试（可选）**：

- 网络错误时自动重试 1 次
- 超时错误时不自动重试

## 4. 技术要点

### 4.1 互斥逻辑实现

**监控模式与本地预览互斥**：

**方案1：服务器端检查**

- APP 发送请求前不检查
- 服务器返回错误码 1001
- APP 根据错误码显示提示

**方案2：APP 端预检查（推荐）**

- APP 维护监控模式和本地预览的状态
- 发送请求前检查状态
- 如果冲突，直接显示提示，不发送请求
- 提升用户体验，减少无效请求

**实现逻辑**：

- 监控模式运行时，禁用本地预览按钮
- 本地预览运行时，禁用监控模式按钮
- 显示互斥提示信息

### 4.2 状态同步机制

**WebSocket 推送方案**：

**优点**：

- 实时性高
- 延迟低
- 节省流量

**实现要点**：

- 监听 WebSocket 消息
- 识别状态变化消息
- 更新本地状态
- 刷新 UI

**轮询查询方案**：

**优点**：

- 实现简单
- 不需要维护长连接

**实现要点**：

- 定时调用状态查询 API
- 比较新旧状态
- 如有变化，更新 UI

### 4.3 错误处理

**网络错误**：

- 显示："网络连接失败，请检查网络"
- 提供重试按钮

**超时错误**：

- 显示："操作超时，请稍后再试"
- 提供重试按钮

**服务器错误**：

- 根据错误码显示对应提示
- 记录错误日志

**未知错误**：

- 显示："未知错误，请稍后再试"
- 记录错误日志

### 4.4 性能优化

**减少无效请求**：

- 按钮点击后立即禁用，防止重复点击
- 实现请求去重（短时间内多次点击只发送一次）

**缓存状态**：

- 缓存设备状态，减少查询请求
- 设置合理的缓存过期时间（如 30 秒）

**懒加载**：

- 只在打开设备控制页面时查询状态
- 不在列表页查询所有设备的状态

## 10. 附录

### 10.1 API 接口详细说明

**启动本地预览**：

- 请求方法：POST
- 请求路径：`/api/device/{device_id}/local_preview`
- 请求头：`Authorization: Bearer {token}`
- 请求体：`{"action": "start"}`
- 成功响应：`{"code": 0, "message": "success", "data": {"status": "running"}}`
- 失败响应：`{"code": 1001, "message": "Monitor mode is active", "data": null}`

**停止本地预览**：

- 请求方法：POST
- 请求路径：`/api/device/{device_id}/local_preview`
- 请求头：`Authorization: Bearer {token}`
- 请求体：`{"action": "stop"}`
- 成功响应：`{"code": 0, "message": "success", "data": {"status": "stopped"}}`
- 失败响应：`{"code": 1005, "message": "System error", "data": null}`

**查询状态**：

- 请求方法：GET
- 请求路径：`/api/device/{device_id}/local_preview/status`
- 请求头：`Authorization: Bearer {token}`
- 成功响应：`{"code": 0, "message": "success", "data": {"local_preview_active": true, "start_time": "2026-05-04T10:30:00Z"}}`
