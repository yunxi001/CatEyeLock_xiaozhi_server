# 本地预览功能 - 服务器端与APP端配合说明

## 文档概述

本文档说明本地预览功能（Local Preview Mode）在服务器端和APP端需要配合实现的功能点。本地预览功能允许用户在 ESP32 的 LCD 屏幕上实时查看摄像头画面，视频数据不发送到服务器，仅在本地显示。

**功能特点：**

- 视频数据在本地显示，不占用网络带宽
- 支持手机 APP 远程控制
- 支持语音命令控制
- 与监控模式、人脸识别功能互斥

---

## 1. 服务器端配合要点

### 1.1 WebSocket 命令转发

#### 1.1.1 接收 APP 请求

服务器需要提供 API 接口，接收 APP 发送的本地预览控制请求：

**请求类型：**

- 启动本地预览
- 停止本地预览

**处理流程：**

1. APP 发送 HTTP/HTTPS 请求到服务器
2. 服务器验证用户权限和设备在线状态
3. 服务器通过 WebSocket 将命令转发给 ESP32
4. 服务器等待 ESP32 响应
5. 服务器将结果返回给 APP

#### 1.1.2 WebSocket 命令格式

**发送给 ESP32 的命令：**

启动本地预览：

```json
{
  "type": "local_preview",
  "action": "start"
}
```

停止本地预览：

```json
{
  "type": "local_preview",
  "action": "stop"
}
```

**ESP32 返回的响应：**

成功响应：

```json
{
  "type": "local_preview",
  "action": "start",
  "status": "success"
}
```

失败响应：

```json
{
  "type": "local_preview",
  "action": "start",
  "status": "error",
  "error": "Camera not available"
}
```

#### 1.1.3 错误码处理

服务器需要识别并处理以下错误情况：

| error 值                  | 含义           | 建议的用户提示                       |
| ------------------------- | -------------- | ------------------------------------ |
| `Camera not available`    | 摄像头不可用   | "摄像头暂时不可用，请稍后再试"       |
| `Monitor mode active`     | 监控模式运行中 | "监控模式正在运行，请先关闭监控模式" |
| `Face recognition active` | 人脸识别运行中 | "人脸识别正在进行，请稍后再试"       |
| `System error`            | 系统错误       | "系统错误，请稍后再试"               |

### 1.2 语音命令处理

#### 1.2.1 STT + LLM 意图识别

服务器需要在语音识别和意图识别模块中添加本地预览相关的触发词和意图处理。

**启动本地预览的触发词示例：**

- "显示监控画面"
- "打开监控画面"
- "让我看看门口"
- "打开本地预览"
- "屏幕显示摄像头"

**停止本地预览的触发词示例：**

- "关闭监控画面"
- "隐藏监控画面"
- "关闭本地预览"
- "关闭屏幕显示"

#### 1.2.2 意图识别后的处理

**处理流程：**

1. 用户通过语音说出触发词
2. 语音数据发送到服务器
3. 服务器进行 STT（语音转文字）
4. 服务器使用 LLM 识别用户意图
5. 识别到本地预览意图后，发送相应的 WebSocket 命令到 ESP32
6. ESP32 执行并返回响应
7. 服务器可选择性地通过 TTS 语音反馈给用户

**意图分类：**

- `intent: start_local_preview` → 发送 `{"type": "local_preview", "action": "start"}`
- `intent: stop_local_preview` → 发送 `{"type": "local_preview", "action": "stop"}`

#### 1.2.3 语音反馈（可选）

服务器可以根据 ESP32 的响应，生成语音反馈：

| 场景         | 建议的语音反馈                       |
| ------------ | ------------------------------------ |
| 启动成功     | "已打开本地预览"                     |
| 停止成功     | "已关闭本地预览"                     |
| 摄像头不可用 | "摄像头暂时不可用"                   |
| 监控模式冲突 | "监控模式正在运行，无法启动本地预览" |
| 人脸识别冲突 | "人脸识别正在进行，请稍后再试"       |

### 1.3 互斥检查（可选）

服务器端可以选择性地实现互斥检查，提前告知用户冲突情况，提升用户体验。

**互斥规则：**

1. 本地预览与监控模式互斥
2. 本地预览与人脸识别互斥

**实现方式：**

- 服务器维护设备状态（监控模式是否运行、人脸识别是否进行中）
- 在转发命令前检查状态
- 如果冲突，直接返回错误给 APP，不发送命令到 ESP32

**注意：** ESP32 端已经实现了完整的互斥检查，服务器端的检查是可选的，主要用于提升用户体验。

### 1.4 设备状态管理

#### 1.4.1 状态维护

服务器需要维护设备的本地预览状态：

**状态字段：**

- `local_preview_active`: boolean - 本地预览是否运行中

**状态更新时机：**

- 收到 ESP32 的成功响应时，更新状态为 true/false
- 设备离线时，重置状态为 false
- 设备重启时，重置状态为 false

#### 1.4.2 状态查询

APP 可能需要查询设备当前是否正在本地预览，服务器需要提供查询接口。

**查询方式：**

- 方式1：服务器维护状态，直接返回
- 方式2：服务器向 ESP32 查询（ESP32 需要实现状态查询接口）

## 2. APP 端配合要点

### 2.1 用户界面设计

#### 2.1.1 控制按钮

**位置建议：**

- 放在设备控制页面
- 可以与"监控模式"按钮并列显示

**按钮状态：**

- 未启动：显示"打开本地预览"或图标
- 运行中：显示"关闭本地预览"或图标（高亮状态）
- 禁用：监控模式运行中时，禁用本地预览按钮

**交互设计：**

- 点击按钮发送请求到服务器
- 显示加载状态（等待响应）
- 根据响应更新按钮状态和提示信息

#### 2.1.2 状态指示

**显示内容：**

- 本地预览是否运行中
- 运行时长（可选）
- 互斥冲突提示

**示例界面：**

```
┌─────────────────────────────┐
│  设备控制                    │
├─────────────────────────────┤
│                             │
│  [监控模式]  [本地预览]     │
│   (运行中)    (未启动)      │
│                             │
│  提示：监控模式运行时，      │
│  无法启动本地预览            │
│                             │
└─────────────────────────────┘
```

### 2.2 API 调用

#### 2.2.1 启动本地预览

**请求示例：**

```
POST /api/device/{device_id}/local_preview
Content-Type: application/json

{
  "action": "start"
}
```

**响应示例（成功）：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "running"
  }
}
```

**响应示例（失败）：**

```json
{
  "code": 1001,
  "message": "Monitor mode is active",
  "data": null
}
```

#### 2.2.2 停止本地预览

**请求示例：**

```
POST /api/device/{device_id}/local_preview
Content-Type: application/json

{
  "action": "stop"
}
```

**响应示例：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "stopped"
  }
}
```

#### 2.2.3 查询状态

**请求示例：**

```
GET /api/device/{device_id}/local_preview/status
```

**响应示例：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "local_preview_active": true,
    "start_time": "2026-05-04T10:30:00Z"
  }
}
```

### 2.3 错误处理

#### 2.3.1 错误码定义

APP 需要处理以下错误情况：

| 错误码 | 含义           | 用户提示                             |
| ------ | -------------- | ------------------------------------ |
| 0      | 成功           | 操作成功                             |
| 1001   | 监控模式运行中 | "监控模式正在运行，请先关闭监控模式" |
| 1002   | 人脸识别运行中 | "人脸识别正在进行，请稍后再试"       |
| 1003   | 摄像头不可用   | "摄像头暂时不可用，请稍后再试"       |
| 1004   | 设备离线       | "设备离线，无法操作"                 |
| 1005   | 系统错误       | "系统错误，请稍后再试"               |
| 1006   | 权限不足       | "您没有权限执行此操作"               |

#### 2.3.2 超时处理

**超时设置：**

- 请求超时：10 秒
- 如果超时，提示用户"操作超时，请检查网络连接"

**重试机制：**

- 失败后可以提供"重试"按钮
- 建议最多重试 2 次

### 2.4 用户体验优化

#### 2.4.1 互斥提示

当监控模式运行时，本地预览按钮应该：

- 显示为禁用状态（灰色）
- 显示提示信息："监控模式运行中"
- 点击时弹出提示："请先关闭监控模式"

#### 2.4.2 状态同步

**实时同步：**

- 通过 WebSocket 或轮询方式，实时同步设备状态
- 当其他用户或语音命令改变状态时，APP 界面自动更新

**离线处理：**

- 设备离线时，禁用所有控制按钮
- 显示"设备离线"提示

#### 2.4.3 操作反馈

**加载状态：**

- 点击按钮后，显示加载动画
- 禁用按钮，防止重复点击

**成功反馈：**

- 显示成功提示（Toast 或 Snackbar）
- 更新按钮状态

**失败反馈：**

- 显示错误提示
- 提供重试选项

## 3. 功能对比表

### 3.1 监控模式 vs 本地预览模式

| 特性     | 监控模式                 | 本地预览模式             |
| -------- | ------------------------ | ------------------------ |
| 视频流向 | 发送到服务器和 APP       | 仅在本地 LCD 显示        |
| 网络带宽 | ~1.2 Mbps                | 0（无网络传输）          |
| 查看方式 | APP 远程查看             | 本地 LCD 屏幕查看        |
| 帧率     | 10 FPS                   | 15 FPS                   |
| 分辨率   | 640×480                  | 240×320（固定）          |
| 音频     | 双向音频                 | 无音频                   |
| 互斥关系 | 与本地预览、人脸识别互斥 | 与监控模式、人脸识别互斥 |
| 使用场景 | 远程查看门口情况         | 本地快速查看门口情况     |

### 3.2 控制方式对比

| 控制方式 | 监控模式 | 本地预览模式 |
| -------- | -------- | ------------ |
| APP 控制 | ✅       | ✅           |
| 语音控制 | ✅       | ✅           |
| 按钮控制 | ❌       | ❌           |

## 6. 常见问题

### Q1: 本地预览和监控模式有什么区别？

**A:** 本地预览将视频显示在 ESP32 的 LCD 屏幕上，不占用网络带宽；监控模式将视频发送到服务器和 APP，可以远程查看。

### Q2: 为什么本地预览和监控模式不能同时运行？

**A:** 两者都需要独占摄像头资源，同时运行会导致资源冲突。

### Q3: 语音命令如何触发本地预览？

**A:** 用户说出触发词（如"显示监控画面"），语音发送到服务器，服务器识别意图后发送命令到 ESP32。

### Q4: 服务器端是否必须实现互斥检查？

**A:** 不是必须的。ESP32 端已经实现了完整的互斥检查，服务器端的检查是可选的，主要用于提升用户体验。

### Q5: APP 如何知道本地预览的状态？

**A:** 通过状态查询 API 或 WebSocket 实时推送。
