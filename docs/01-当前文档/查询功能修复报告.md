# 查询功能修复报告

**日期**: 2026-05-09  
**版本**: v1.0  
**修复人员**: AI Assistant

---

## 问题概述

根据 2026-05-09 16:10-16:14 时段的服务器日志和 App 端日志分析，发现以下问题：

### 1. 查询功能缺失

**现象**：

- App 发送 `visitor_intents` 查询请求，服务器返回错误：`未知查询目标: visitor_intents`
- App 发送 `package_alerts` 查询请求，服务器返回错误：`未知查询目标: package_alerts`

**原因**：

- `queryHandler.py` 的 handlers 字典中缺少这两个查询处理器
- 虽然数据库方法 `get_visitor_intents` 和 `get_package_alerts` 已实现，但未在查询处理器中注册

### 2. status_report 数据为 null

**现象**：

- App 显示 `电量 null%`
- 灯光控制时，App 显示的锁状态是旧的缓存数据

**原因**：

- ESP32 没有主动上报状态（或上报频率低）
- 服务器构造 `status_report` 时从缓存读取数据
- 如果缓存为空，`old_state.get("battery")` 返回 `None`
- JSON 序列化后变成 `null`

### 3. 数据库字段类型错误（潜在问题）

**现象**：

- 日志显示：`Incorrect integer value: 'app_1777960149873_qicvyypr0' for column 'user_id'`

**原因**：

- `unlock_logs` 表的 `user_id` 字段是 `INT` 类型
- 远程开锁时，App 用户 ID 是字符串（如 `app_1777960149873_qicvyypr0`）
- 代码尝试将字符串插入到 INT 字段

### 修复 3: 解决远程开锁 user_id 类型错误

**文件**: `main/xiaozhi-server/core/handle/textHandler/logReportHandler.py`

**修改内容**：

在 `_fill_user_id` 方法中，修改远程开锁的处理逻辑：

```python
elif method == "remote":
    # 远程开锁：App 用户 ID 是字符串（如 app_1777960149873_qicvyypr0）
    # 数据库 user_id 字段是 INT 类型，无法存储字符串
    # 因此远程开锁的 user_id 统一设置为 0
    # App 用户信息可以通过其他方式关联（如通过 seq_id 或时间戳）
    if hasattr(conn, "last_remote_unlock") and conn.last_remote_unlock:
        last_unlock = conn.last_remote_unlock
        app_id = last_unlock.get("app_id", "")
        conn.logger.bind(tag=TAG).debug(
            f"远程开锁日志: app_id={app_id}, user_id=0（App ID 为字符串，不存储到 user_id 字段）"
        )
    else:
        conn.logger.bind(tag=TAG).warning(
            "远程开锁日志无法获取 app_id：未找到有效的开锁命令"
        )
    return 0
```

**效果**：

- 远程开锁的 `user_id` 统一存储为 0
- 不再尝试将字符串插入到 INT 字段
- 避免数据库错误

**注意事项**：

- App 用户信息丢失（无法通过 user_id 关联）
- 建议后续优化：
  - 方案 A: 修改数据库表结构，添加 `app_user_id VARCHAR(64)` 字段
  - 方案 B: 创建 App 用户映射表，将字符串 ID 映射到整数 ID

## 后续优化建议

### 1. 主动查询 ESP32 状态

**问题**：设备连接后，如果 ESP32 没有主动上报状态，缓存为空。

**建议**：

- 在设备连接后，服务器主动发送 `query` 命令查询状态
- 使用 ESP32 协议 v5.2 的查询功能：

  ```json
  {
    "type": "query",
    "seq_id": "1702234567890_0",
    "command": "sensors"  // 查询电量、光照
  }

  {
    "type": "query",
    "seq_id": "1702234567890_1",
    "command": "status"   // 查询锁状态、灯状态
  }
  ```

**实现位置**：

- `core/connection.py` 的 ESP32 连接初始化逻辑
- 在 `hello` 消息处理完成后立即查询

### 2. 优化 App 用户 ID 存储

**问题**：远程开锁的 App 用户 ID 是字符串，无法存储到 INT 字段。

**建议方案 A**：修改数据库表结构

```sql
ALTER TABLE unlock_logs
ADD COLUMN app_user_id VARCHAR(64) COMMENT 'App 用户 ID（字符串）';
```

**建议方案 B**：创建 App 用户映射表

```sql
CREATE TABLE app_users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    app_user_id VARCHAR(64) UNIQUE NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 3. 增强错误处理

**建议**：

- 在查询处理器中添加更详细的错误信息
- 区分"数据库不可用"、"查询失败"、"无数据"等不同错误
- 返回更友好的错误消息给 App

### 4. 添加查询缓存

**建议**：

- 对于频繁查询的数据（如设备状态），添加 Redis 缓存
- 减少数据库查询压力
- 提高响应速度
