## 设备端IoT工具

根据代码分析，设备端注册的IoT工具也会包含中文：

```python
# device_iot/iot_executor.py 第147-157行
tool_desc = {
    "type": "function",
    "function": {
        "name": tool_name,
        "description": f"查询{device_desc}的{prop_info['description']}",  # ← 如果device_desc是中文，这里就是中文
        "parameters": {
            "properties": {
                "response_success": {
                    "description": f"查询成功时的友好回复，必须使用{{value}}作为占位符表示查询到的值"  # ← 中文
                },
                "response_failure": {
                    "description": f"查询失败时的友好回复"  # ← 中文
                }
            }
        }
    }
}
```

**如果ESP32设备注册的描述符使用中文，那么生成的工具描述也会包含中文。**

例如：

```python
# 设备端发送的描述符（假设）
{
    "name": "camera",
    "description": "摄像头",  # ← 中文
    "methods": {
        "take_photo": {
            "description": "拍照"  # ← 中文
        }
    }
}

# 生成的工具描述
{
    "name": "camera_take_photo",
    "description": "摄像头 - 拍照",  # ← 中文
    "parameters": {
        "response_success": {
            "description": "操作成功时的友好回复"  # ← 中文
        }
    }
}
```

## 结论

1. **所有服务端插件的工具描述都包含中文字符**
2. **设备端IoT工具如果使用中文描述符，生成的工具描述也会包含中文**
3. **这些中文描述会被传递给OpenAI API**
4. **OpenAI SDK在处理streaming响应时，如果内部使用ASCII编码，就会触发编码错误**

## 这就是ASCII编码错误的根本原因

当用户问"你可以拍照吗？"时：

1. LLM接收到所有工具描述（包含大量中文）
2. LLM识别用户意图，准备调用拍照工具
3. OpenAI SDK在streaming过程中返回tool_calls
4. tool_calls中包含中文字符（工具名称、描述、参数等）
5. SDK内部某个环节使用了ASCII编码
6. 触发错误：`'ascii' codec can't encode characters in position 7-8`

## 修复建议优先级

### 方案1：升级OpenAI SDK ⭐⭐⭐⭐⭐

```bash
pip install --upgrade openai
```

最新版本可能已修复此问题。

### 方案2：在OpenAI Provider中添加编码处理 ⭐⭐⭐⭐

修改`openai.py`，捕获并处理Unicode编码错误。

### 方案3：切换到其他LLM ⭐⭐⭐⭐

使用ChatGLM或Doubao，它们对中文支持更好。

### 方案4：工具描述改用英文 ⭐⭐

不推荐，会影响LLM理解准确性。
