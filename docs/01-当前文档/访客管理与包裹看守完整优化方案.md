## 一、项目背景

### 1.1 当前存在的三大问题

| 问题编号 | 问题描述 | 影响范围 |
|----------|----------|----------|
| 问题1 | **PIR重复触发**：同一人在门口停留时，PIR每秒上报一次，导致访客识别流程被重复触发 | 访客管理、包裹看守 |
| 问题2 | **访客管理体验差**：路人路过也会触发识别，停留时间短的访客无法完成识别 | 访客管理 |
| 问题3 | **包裹看守资源消耗大**：无论是否有人，每5秒拍照一次，8小时消耗5760次识别资源 | 包裹看守 |

### 1.2 ESP32 PIR上报机制说明

ESP32 PIR传感器的上报行为：
- **上报频率**：每秒上报一次（检测到人体时持续上报）
- **param字段**：表示人体持续停留时间（秒），每次上报递增
- **停止条件**：人体离开后停止上报

```
时间轴示例：
t=0s: PIR上报 param=1  (人体出现)
t=1s: PIR上报 param=2  (持续停留)
t=2s: PIR上报 param=3  (持续停留)
t=3s: PIR上报 param=4  (持续停留)
t=4s: 无上报           (人体离开)
```

### 1.3 三大优化目标

1. **修复PIR重复触发**：同一次人体停留只触发一次业务逻辑
2. **优化访客管理体验**：停留3秒以上才触发识别，路人路过不触发
3. **降低包裹看守资源消耗**：事件驱动模式，有人才拍照，节省94.8%资源

## 三、方案详细设计

### 3.1 核心数据结构

`ConnectionHandler` 新增PIR状态属性：

```python
class ConnectionHandler:
    def __init__(self):
        # ... 现有属性 ...

        # PIR状态管理（新增）
        self.pir_detected: bool = False          # 当前是否检测到人体
        self.last_pir_time: float = 0.0          # 最后一次PIR上报时间戳
        self.pir_duration: int = 0               # 当前人体停留时长（秒）
        self.visitor_processing: bool = False    # 是否正在处理访客（防重复触发）
```

### 3.2 PIR超时判断逻辑

**超时阈值：2秒**（PIR每秒上报，2秒未收到新上报则认为人体已离开）

```python
def is_pir_timeout(conn: ConnectionHandler, timeout: float = 2.0) -> bool:
    """判断PIR是否已超时（人体是否已离开）"""
    if not conn.pir_detected:
        return True
    elapsed = time.time() - conn.last_pir_time
    return elapsed > timeout
```

### 3.3 方案1详细设计：PIR重复触发修复

**核心机制**：使用 `visitor_processing` 标志位防止重复触发

async def _handle_pir_event(self, conn, param):

    if conn.visitor_processing:

### 3.4 方案2详细设计：访客管理优化

#### 完整流程图

```
PIR上报 (每秒)
    │
    ▼
更新PIR状态 (pir_detected=True, last_pir_time=now, pir_duration=param)
    │
    ▼
visitor_processing == True?
    │ 是 → 跳过，等待下次上报
    │ 否
    ▼
param >= 3? (停留满3秒?)
    │ 否 → 跳过，等待下次上报
    │ 是
    ▼
设置 visitor_processing = True
    │
    ▼
调用 handle_visitor(conn)
    │
    ├── 开始人脸识别重试循环
    │       │
    │       ▼
    │   检查PIR状态 (is_pir_timeout?)
    │       │ 是 → 返回 "pir_interrupted"
    │       │ 否
    │       ▼
    │   执行人脸识别
    │       │
    │       ├── 识别成功 → 开门/拒绝
    │       └── 识别失败 → 重试（最多3次）
    │
    ▼
finally: visitor_processing = False
```

#### 三个场景分析

**场景A：路人路过（停留 < 3秒）**
```
t=0s: PIR上报 param=1 → 停留不足3秒，跳过
t=1s: PIR上报 param=2 → 停留不足3秒，跳过
t=2s: 人离开，PIR停止上报
结果：不触发识别，✅ 正确行为
```

**场景B：访客停留（停留 >= 3秒）**
```
t=0s: PIR上报 param=1 → 跳过
t=1s: PIR上报 param=2 → 跳过
t=2s: PIR上报 param=3 → 触发识别！设置 visitor_processing=True
t=3s: PIR上报 param=4 → visitor_processing=True，跳过（防重复）
t=4s: 识别完成，visitor_processing=False
结果：只触发一次识别，✅ 正确行为
```

**场景C：识别中途离开**
```
t=0s: PIR上报 param=3 → 触发识别
t=1s: 开始第1次识别尝试
t=2s: 人离开，PIR停止上报
t=4s: 第1次识别失败，准备重试
      → 检查PIR状态：距上次上报已2秒，超时！
      → 返回 "pir_interrupted"，中止识别
结果：及时中止，不浪费资源，✅ 正确行为
```

#### 关键代码示例

```python
# eventReportHandler.py
async def _handle_pir_event(self, conn, param):
    # 1. 更新PIR状态
    conn.pir_detected = True
    conn.last_pir_time = time.time()
    conn.pir_duration = param

    # 2. 防重复触发
    if conn.visitor_processing:
        return

    # 3. 停留阈值检查（3秒）
    pir_stay_threshold = self.config.get("pir_stay_threshold", 3)
    if param < pir_stay_threshold:
        return

    # 4. 触发访客处理
    asyncio.create_task(self.doorlock_handler.handle_visitor(conn))


# face_recognition_handler.py
async def recognize_with_retry(self, conn, max_retries=3):
    for attempt in range(max_retries):
        # 每次重试前检查PIR状态
        if is_pir_timeout(conn):
            logger.info(f"PIR超时，中止识别（第{attempt+1}次尝试）")
            return "pir_interrupted"

        result = await self._do_recognize()
        if result["success"]:
            return result

        await asyncio.sleep(1)

    return {"success": False, "reason": "max_retries_exceeded"}


# doorlock_intent_handler.py
async def handle_visitor(self, conn):
    conn.visitor_processing = True
    try:
        result = await self.face_recognition.recognize_with_retry(conn)

        if result == "pir_interrupted":
            logger.info("访客已离开，中止处理")
            return

        # 处理识别结果...
    finally:
        conn.visitor_processing = False  # 确保标志位被清除
```

#### 关键代码示例

```python
# package_guard_manager.py

class PackageGuardManager:

    async def start_monitoring(self, device_id: str, session_id: str, conn):
        """启动包裹看守（事件驱动模式）"""
        logger.info(f"包裹看守启动，设备: {device_id}")

        while self._is_monitoring(device_id):
            # 等待PIR触发（低功耗等待）
            await self._wait_for_pir_detection(conn)

            if not self._is_monitoring(device_id):
                break

            # PIR触发，进入高频监控
            logger.info("检测到人体，进入高频监控模式")
            await self._high_frequency_monitoring(device_id, session_id, conn)

        logger.info(f"包裹看守结束，设备: {device_id}")

    async def _wait_for_pir_detection(self, conn):
        """等待PIR触发（协程挂起，不消耗CPU）"""
        while True:
            if conn.pir_detected and not is_pir_timeout(conn):
                return  # PIR已触发
            await asyncio.sleep(0.5)  # 每0.5秒检查一次

    async def _high_frequency_monitoring(self, device_id: str, session_id: str, conn):
        """高频监控模式（有人时每3秒拍照）"""
        monitoring_interval = self.config.get("monitoring_interval", 3)

        while self._is_monitoring(device_id):
            # 检查人是否已离开
            if self._check_pir_status(conn):
                logger.info("人体已离开，退出高频监控")
                return

            # 执行拍照和分析
            await self._capture_and_analyze(device_id, session_id)
            await asyncio.sleep(monitoring_interval)

    def _check_pir_status(self, conn) -> bool:
        """检查PIR是否超时（人是否已离开）"""
        return is_pir_timeout(conn, timeout=2.0)
```

## 六、风险评估

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| PIR超时阈值不准确（硬件差异导致上报间隔不稳定） | 中 | 中 | 提供 `pir_timeout` 配置项，默认2秒，可调整 |
| 停留阈值过短（3秒太短，仍有误触发） | 低 | 低 | 提供 `pir_stay_threshold` 配置项，可调整 |
| 停留阈值过长（3秒太长，真实访客等待时间长） | 低 | 中 | 同上，根据实际场景调整 |
| 并发访客处理冲突（多个PIR事件同时触发） | 低 | 高 | 使用设备级别锁（`visitor_processing` 标志位） |
| 包裹看守等待PIR时错过事件 | 低 | 中 | 0.5秒轮询检查，响应延迟可接受 |
