## 根本原因确认

```yaml
  url: # ← 空的
```

→ 系统使用本地 `config.yaml` 的 FunASR 配置

```yaml

  url: http://某个地址:8002/xiaozhi # ← 有值
  secret: 2c7b52c9-a9a3-4025-a7b7-51d8b44ab35b
```

→ 系统从 manager-api 加载配置，使用 DoubaoStreamASR

### 配置加载逻辑

```python
if manager_api_url:
```

当 `manager-api.url` 为空时：

1. 不会显示"从API读取配置"

3. `config.yaml` 中 `ASR: FunASR`
4. FunASR 输出进度条（包含Unicode字符）
5. 触发 ASCII 编码错误

## ASCII 编码错误的真正原因

### 不是进度条！

之前我们认为是 FunASR 的进度条（`rtf_avg`）导致的，但从日志看：

- **错误日志中没有出现 `rtf_avg` 进度条**
- **错误发生在 LLM 调用工具时**

### 真正的原因

错误发生在：

```
core.providers.llm.openai.openai - ERROR - Error in function call streaming: 'ascii' codec can't encode characters in position 7-8: ordinal not in range(128)
```

这是在调用 OpenAI API 时，传递工具列表时触发的编码错误。

**可能的原因**：

1. 工具描述中包含中文字符
2. 系统输出流使用 ASCII 编码
3. 在序列化工具 JSON 时触发编码错误

### 为什么 DoubaoStreamASR 不会出错？

因为配置来源不同：

- **FunASR**：使用本地 `config.yaml`，可能某些配置或环境变量导致输出流使用 ASCII 编码
- **DoubaoStreamASR**：从 manager-api 加载配置，环境配置正确，输出流使用 UTF-8 编码
