# 统一智能看护对话模式 - 用户手册

## 概述

统一智能看护对话模式是智能门锁系统的核心功能，将访客对话和快递看护统一到一个智能流程中。访客可以正常与门锁 AI 对话，同时 AI 在后台监控快递安全，提供无缝的用户体验。

## 功能特性

### 核心优势

1. **无缝体验**
   - 访客对话不受看护模式影响
   - 看护监控在后台静默运行
   - 一次交互完成两项任务

2. **智能监控**
   - 基于访客行为实时检测威胁
   - 高威胁时立即警告并打断对话
   - 对话结束后自动检查快递状态

3. **Token 优化**
   - 仅第一轮传入基准图片
   - 后续依赖 AI 上下文理解
   - 10 轮对话仅消耗 ~100K Token

4. **实时拍照**
   - 对话期间每 5 秒自动拍照
   - 使用最新照片进行分析
   - 不阻塞对话流程

5. **完整记录**
   - 自动生成访客意图总结
   - 记录快递状态变化
   - 保存完整对话历史

## 工作原理

### 对话流程

```
访客到访
  ↓
人脸识别（未识别或无权限）
  ↓
启动统一模式对话
  ├─ 检查看护模式状态
  ├─ 启动定时拍照（每 5 秒）
  └─ 播放主动问候
  ↓
对话进行中
  ├─ 访客：我是来送快递的
  ├─ AI：好的，请问快递放在哪里？
  ├─ 访客：我放门口了
  └─ AI：收到，我会帮您看护快递
  ↓
对话结束
  ├─ 停止定时拍照
  ├─ 检查快递状态（如果看护激活）
  ├─ 生成意图总结
  ├─ 保存访问记录
  └─ 发送 App 通知
```

### 看护监控

**监控时机**：

- 对话进行中：基于访客行为实时检测
- 对话结束后：对比基准图片和当前图片

**威胁等级**：

- **低威胁（low）**：路人经过、主人取快递
- **中威胁（medium）**：翻看快递、长时间停留
- **高威胁（high）**：非主人拿走快递、破坏快递

**处理方式**：

- 中威胁：记录日志，继续对话
- 高威胁：立即播放警告，可打断对话

## 使用场景

### 场景 1：快递员送快递

**看护模式**：未激活

```
访客：你好，我是来送快递的
AI：好的，请问快递放在哪里？
访客：我放门口了
AI：收到，请问需要我帮您看护快递吗？
访客：是的，麻烦了
AI：好的，我会帮您看护快递，有人靠近会通知您
```

**结果**：

- 启用看护模式
- 保存基准图片
- 记录访问：意图类型 = delivery

---

### 场景 2：访客取快递（看护激活）

**看护模式**：已激活

```
访客：你好，我来拿一下快递
AI：好的，请问您是？
访客：我是隔壁邻居，帮朋友拿快递
AI：（检测到访客靠近快递）请问您有主人的授权吗？
访客：有的，他让我来拿
AI：好的，请稍等，我需要通知主人确认
```

**结果**：

- 检测到中威胁（翻看快递）
- 发送 App 通知给主人
- 记录访问：意图类型 = visit

---

### 场景 3：可疑人员偷快递（看护激活）

**看护模式**：已激活

```
访客：（沉默，直接靠近快递）
AI：您好，请问有什么可以帮您？
访客：（继续拿快递）
AI：⚠️ 警告！检测到未授权人员拿走快递，已通知主人！
```

**结果**：

- 检测到高威胁（拿走快递）
- 立即播放警告语音
- 发送紧急通知给主人
- 记录访问：意图类型 = other，威胁等级 = high

---

### 场景 4：主人取快递（看护激活）

**看护模式**：已激活

```
（人脸识别：主人）
系统：自动开门，欢迎回家
（主人取走快递）
```

**结果**：

- 不启动对话（主人有权限）
- 看护模式保持激活（不自动关闭）
- 不发送警报（主人取快递是正常行为）

## 启用/禁用统一模式

### 方式 1：通过配置文件

编辑 `config/doorlock_config.yaml`：

```yaml
# 统一模式配置
unified_mode:
  enabled: true # true = 启用，false = 禁用
```

**重启服务生效**：

```bash
cd main/xiaozhi-server
python app.py
```

---

### 方式 2：通过 AI 对话

**启用看护模式**：

```
访客：我是来送快递的，快递放门口了
AI：好的，我会帮您看护快递
（AI 自动调用 enable_package_guard 工具）
```

**禁用看护模式**：

```
主人：快递我已经拿走了
AI：好的，我会关闭看护模式
（AI 自动调用 disable_package_guard 工具）
```

---

### 方式 3：通过 App

1. 打开智能门锁 App
2. 进入设备设置
3. 找到"快递看护"选项
4. 开启/关闭看护模式

## 配置说明

### 基础配置

```yaml
# config/doorlock_config.yaml

# 统一模式配置
unified_mode:
  enabled: true # 启用统一模式

  # 对话配置
  dialogue:
    max_rounds: 10 # 最大对话轮次
    timeout_seconds: 30 # 沉默超时时间（秒）

  # 看护配置
  guard:
    threat_detection: "behavior_based" # 基于行为触发
    report_threshold: "medium" # 威胁等级≥medium 时报告

  # Token 优化
  token_optimization:
    baseline_image_once: true # 仅第一轮传入基准图片
    reuse_context: true # 依赖 AI 上下文理解

# 照片缓存配置
photo_cache:
  interval_seconds: 5 # 拍照间隔（秒）
  max_cache_size: 10 # 最大缓存数量

# 性能配置
performance:
  vllm_limits:
    model_context_limit: 262144 # 模型上下文窗口
    max_input_tokens: 260096 # 最大输入 Token
    max_output_tokens: 32768 # 最大输出 Token
    max_image_tokens: 16384 # 最大图片 Token
    tokens_per_image: 7000 # 每张图片 Token 数
    input_warning_ratio: 0.8 # 输入 Token 警告阈值
    total_warning_ratio: 0.8 # 总 Token 警告阈值
```

### 配置项说明

| 配置项                         | 默认值           | 说明                         |
| ------------------------------ | ---------------- | ---------------------------- |
| `unified_mode.enabled`         | `true`           | 是否启用统一模式             |
| `dialogue.max_rounds`          | `10`             | 最大对话轮次，超过后自动结束 |
| `dialogue.timeout_seconds`     | `30`             | 沉默超时时间，超过后自动结束 |
| `guard.threat_detection`       | `behavior_based` | 威胁检测方式（基于行为）     |
| `guard.report_threshold`       | `medium`         | 报告阈值（≥medium 时报告）   |
| `photo_cache.interval_seconds` | `5`              | 拍照间隔（秒）               |
| `photo_cache.max_cache_size`   | `10`             | 最大缓存照片数量             |

## 性能参考

### Token 消耗

| 场景                | 对话轮次 | Token 消耗 | 说明                                        |
| ------------------- | -------- | ---------- | ------------------------------------------- |
| 看护激活（10 轮）   | 10       | ~100K      | 第一轮 14K + 后续 9×7K + 检查 15K + 总结 8K |
| 看护激活（5 轮）    | 5        | ~65K       | 第一轮 14K + 后续 4×7K + 检查 15K + 总结 8K |
| 仅对话模式（10 轮） | 10       | ~85K       | 第一轮 7K + 后续 9×7K + 总结 8K             |

### 响应时间

| 操作           | 目标时间 | 说明                  |
| -------------- | -------- | --------------------- |
| 单轮对话       | <5 秒    | 包含 ASR + VLLM + TTS |
| 拍照操作       | <1 秒    | ESP32 拍照            |
| 对话结束后处理 | <10 秒   | 包含检查和总结        |
| 完整对话流程   | <2 分钟  | 10 轮对话             |

### 内存占用

| 组件              | 内存占用 | 说明        |
| ----------------- | -------- | ----------- |
| 照片缓存（10 张） | ~1-2MB   | Base64 编码 |
| 对话历史（10 轮） | ~10KB    | 文本数据    |
| 会话数据          | ~100KB   | 临时数据    |

## 常见问题

### Q1：统一模式和分离模式有什么区别？

**分离模式**（旧版）：

- 看护模式激活时，访客无法对话
- 对话和看护是两个独立流程
- 用户体验不连贯

**统一模式**（新版）：

- 看护模式激活时，访客仍可对话
- 对话和看护在一个流程中
- 用户体验无缝

---

### Q2：看护模式会自动关闭吗？

**不会自动关闭**。看护模式需要手动关闭或通过 AI 对话关闭：

- 主人取快递后，AI 判断为低威胁，看护模式保持激活
- 需要主人明确告知"快递已取走"，AI 才会关闭看护模式
- 或者通过 App 手动关闭

---

### Q3：如何查看快递状态？

**方式 1：通过 App**

- 打开智能门锁 App
- 查看"快递看护"页面
- 显示当前状态和历史记录

**方式 2：通过对话**

```
主人：快递还在吗？
AI：是的，快递还在门口，状态正常
```

---

### Q4：高威胁警告会打断对话吗？

**会**。检测到高威胁时：

1. 立即播放警告语音
2. 发送紧急通知给主人
3. 可以打断当前对话
4. 记录详细日志

---

### Q5：定时拍照会影响对话速度吗？

**不会**。定时拍照在后台异步运行：

- 不阻塞对话流程
- 使用最新缓存照片
- 对话中不需要等待拍照

---

### Q6：如何优化 Token 消耗？

**系统已自动优化**：

- 仅第一轮传入基准图片
- 后续依赖 AI 上下文理解
- 对话历史自动截断

**用户可调整**：

- 减少最大对话轮次（`max_rounds`）
- 缩短沉默超时时间（`timeout_seconds`）
- 降低拍照频率（`interval_seconds`）

---

### Q7：如何禁用统一模式？

编辑 `config/doorlock_config.yaml`：

```yaml
unified_mode:
  enabled: false # 禁用统一模式
```

**效果**：

- 回退到分离模式
- 看护模式激活时无法对话
- Token 消耗降低

---

### Q8：主人取快递会触发警报吗？

**不会**。系统会识别主人：

- 人脸识别确认身份
- 判定为低威胁正常行为
- 不发送警报
- 看护模式保持激活

## 最佳实践

### 1. 合理设置对话轮次

```yaml
dialogue:
  max_rounds: 10 # 推荐 5-10 轮
```

- 太少：可能无法充分了解访客意图
- 太多：Token 消耗增加，对话时间过长

---

### 2. 及时关闭看护模式

**推荐做法**：

- 快递取走后，通过 App 或对话关闭看护模式
- 避免长时间激活导致误报

**不推荐**：

- 长期激活看护模式
- 忘记关闭导致资源浪费

---

### 3. 定期查看访问记录

**通过 App 查看**：

- 访客到访时间
- 对话内容摘要
- 快递状态变化
- 威胁等级记录

**用途**：

- 了解访客情况
- 发现可疑行为
- 优化看护策略

---

### 4. 合理配置拍照间隔

```yaml
photo_cache:
  interval_seconds: 5 # 推荐 3-10 秒
```

- 太短：资源消耗增加
- 太长：可能错过关键行为

## 故障排查

### 问题 1：对话无响应

**可能原因**：

- VLLM 服务不可用
- 网络连接问题
- Token 超限

**解决方案**：

1. 检查 VLLM 服务状态
2. 查看日志文件
3. 重启服务

---

### 问题 2：拍照失败

**可能原因**：

- ESP32 摄像头故障
- 网络连接问题
- 存储空间不足

**解决方案**：

1. 检查 ESP32 状态
2. 重启设备
3. 清理存储空间

---

### 问题 3：Token 超限

**可能原因**：

- 对话轮次过多
- 对话历史过长
- 图片过多

**解决方案**：

1. 减少最大对话轮次
2. 启用对话历史截断
3. 降低拍照频率

---

### 问题 4：误报警告

**可能原因**：

- 基准图片不准确
- 光线变化
- AI 判断错误

**解决方案**：

1. 更新基准图片
2. 调整威胁阈值
3. 查看日志分析原因
