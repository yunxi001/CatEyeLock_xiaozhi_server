# 配置加载逻辑详解

## 配置加载流程图

```
启动 app.py
    ↓
调用 load_config() (config/settings.py)
    ↓
调用 load_config() (config/config_loader.py)
    ↓
检查缓存 (cache_manager)
    ↓
读取两个配置文件:
  - config.yaml (默认配置)
  - data/.config.yaml (用户配置)
    ↓
判断: manager-api.url 是否有值？
    ↓
   是 ↓                     否 ↓
从API获取配置          合并本地配置
    ↓                         ↓
get_config_from_api()   merge_configs()
    ↓                         ↓
返回API配置              返回合并配置
    ↓                         ↓
    └─────────┬───────────────┘
              ↓
      缓存配置并返回
```

## 核心代码分析

### 1. 主入口：`config/config_loader.py` 的 `load_config()`

```python
def load_config():
    """加载配置文件"""
    from core.utils.cache.manager import cache_manager, CacheType

    # 1. 检查缓存
    cached_config = cache_manager.get(CacheType.CONFIG, "main_config")
    if cached_config is not None:
        return cached_config

    # 2. 读取两个配置文件
    default_config_path = get_project_dir() + "config.yaml"
    custom_config_path = get_project_dir() + "data/.config.yaml"

    default_config = read_config(default_config_path)
    custom_config = read_config(custom_config_path)

    # 3. 关键判断：manager-api.url 是否有值
    if custom_config.get("manager-api", {}).get("url"):
        # 从API获取配置
        config = get_config_from_api(custom_config)
    else:
        # 合并本地配置
        config = merge_configs(default_config, custom_config)

    # 4. 初始化目录
    ensure_directories(config)

    # 5. 缓存配置
    cache_manager.set(CacheType.CONFIG, "main_config", config)
    return config
```

### 2. 关键判断逻辑

```python
if custom_config.get("manager-api", {}).get("url"):
    # 条件为真：manager-api.url 有值
    config = get_config_from_api(custom_config)
else:
    # 条件为假：manager-api.url 为空或不存在
    config = merge_configs(default_config, custom_config)
```

**这就是导致初始化日志不同的根本原因！**

## 两种配置加载路径

### 路径1：从API获取配置（正确的方式）

**触发条件**：

```yaml
# data/.config.yaml
manager-api:
  url: http://192.168.1.100:8002/xiaozhi # ← 有值
  secret: 2c7b52c9-a9a3-4025-a7b7-51d8b44ab35b
```

**执行流程**：

```python
def get_config_from_api(config):
    """从Java API获取配置"""
    # 1. 初始化API客户端
    init_service(config)  # 创建 ManageApiClient 实例

    # 2. 调用API获取服务器配置
    config_data = get_server_config()  # POST /config/server-base
    if config_data is None:
        raise Exception("Failed to fetch server config from API")

    # 3. 标记配置来源
    config_data["read_config_from_api"] = True

    # 4. 保留本地的 manager-api 配置
    config_data["manager-api"] = {
        "url": config["manager-api"].get("url", ""),
        "secret": config["manager-api"].get("secret", ""),
    }

    # 5. server配置以本地为准
    if config.get("server"):
        config_data["server"] = {...}

    return config_data
```

**日志输出**：

```python
# config/settings.py 的 check_config_file()
if config.get("read_config_from_api", False):
    print("从API读取配置")  # ← 这里输出日志
```

**结果**：

- ✅ 输出："从API读取配置"
- ✅ 使用API返回的 `selected_module`（包含 DoubaoStreamASR）
- ✅ `config["read_config_from_api"] = True`

### 路径2：合并本地配置（错误的方式）

**触发条件**：

```yaml
# data/.config.yaml
manager-api:
  url: # ← 空的或不存在
  secret: 2c7b52c9-a9a3-4025-a7b7-51d8b44ab35b
```

**执行流程**：

```python
def merge_configs(default_config, custom_config):
    """
    递归合并配置，custom_config优先级更高
    """
    # 1. 合并 config.yaml 和 data/.config.yaml
    # 2. data/.config.yaml 的值会覆盖 config.yaml
    # 3. 但如果 data/.config.yaml 中没有 selected_module
    #    则使用 config.yaml 中的 selected_module

    merged = dict(default_config)
    for key, value in custom_config.items():
        if key in merged and isinstance(merged[key], Mapping):
            merged[key] = merge_configs(merged[key], value)
        else:
            merged[key] = value
    return merged
```

**日志输出**：

```python
# config/settings.py 的 check_config_file()
if config.get("read_config_from_api", False):
    print("从API读取配置")
else:
    # 什么都不输出！  # ← 这就是为什么没有日志
```

**结果**：

- ❌ 没有输出任何日志
- ❌ 使用 `config.yaml` 中的 `selected_module`（包含 FunASR）
- ❌ `config["read_config_from_api"]` 不存在或为 False

## 为什么会使用不同的 ASR 模块？

## 为什么错误日志中 selected_module 是 00000000000000？

### 日志格式定义

**文件**：`main/xiaozhi-server/config/logger.py`

```python
def formatter(record):
    """为没有 tag 的日志添加默认值，并处理动态模块字符串"""
    record["extra"].setdefault("tag", record["name"])
    # 如果没有设置 selected_module，使用默认值
    record["extra"].setdefault("selected_module", "00000000000000")
    record["selected_module"] = record["extra"]["selected_module"]
    return record["message"]
```

### selected_module 的设置时机

`selected_module` 是在**连接建立后**才设置的，不是在启动时设置的。

**文件**：`main/xiaozhi-server/core/connection.py`

```python
# 在连接初始化时
selected_module_str = build_module_string(self.config["selected_module"])
self.logger = create_connection_logger(selected_module_str)
```

### 为什么错误日志始终显示 00000000000000？

因为：

1. 启动时的日志使用的是全局 logger，还没有设置 `selected_module`
2. 使用默认值 `"00000000000000"`
3. 只有在设备连接后，才会创建带有正确 `selected_module` 的连接 logger

但在正确的配置下，连接后的日志会显示正确的 `selected_module`（如 `SiDoAlHushcaQw`）。

## 总结

### 配置加载的两条路径

| 路径      | 触发条件               | 配置来源         | ASR模块         | 日志输出        |
| --------- | ---------------------- | ---------------- | --------------- | --------------- |
| **路径1** | `manager-api.url` 有值 | API              | DoubaoStreamASR | "从API读取配置" |
| **路径2** | `manager-api.url` 为空 | 本地 config.yaml | FunASR          | 无输出          |

### 关键判断代码

```python
# config/config_loader.py 第 33 行
if custom_config.get("manager-api", {}).get("url"):
    # 路径1：从API获取配置
    config = get_config_from_api(custom_config)
else:
    # 路径2：使用本地配置
    config = merge_configs(default_config, custom_config)
```

### 为什么会出现 ASCII 编码错误？

1. 使用本地配置时，ASR 模块为 FunASR
2. FunASR 是本地模型，可能在某些环境下导致输出流使用 ASCII 编码
3. 当调用 OpenAI API 传递工具列表时，中文字符无法用 ASCII 编码
4. 触发 `'ascii' codec can't encode characters` 错误

### 解决方案

确保 `data/.config.yaml` 中 `manager-api.url` 有值，系统就会从API获取配置，使用 DoubaoStreamASR，避免编码问题。
